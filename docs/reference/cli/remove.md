# workler remove

Delete a workspace.

```bash
workler remove <name> [--force]
```

`workler rm` is an alias.

## Behavior

Deletes `.worktrees/<name>` after two independent checks: local files, then Git commit preservation. Neither check creates a backup:

- Refuses if the workspace has **local data** — uncommitted changes to tracked files, staged changes, untracked files, and ignored files. Deletion is forever, so this guard is deliberately stricter than the tracked-only dirty check used by [`status`](/reference/cli/status) and [`sync`](/reference/cli/sync): a gitignored database, a hand-made `.env`, and nested `.worktrees/` all count. Two things do not count:
  - **What `.workler` produces.** The destinations of the project's [copy and link rules](/reference/configuration), while they are what `apply` makes of their source (the source exists in the main project and is reached through real folders, since `apply` skips an absent source and refuses one behind a symbolic link, and the destination is a link to it or a copy with its content), and the paths of its `setup --if-missing` lines that a guarded command created in this workspace, while the entry there is still the one it made (`node_modules` say; [`setup` records them](/guide/setup#only-when-something-is-missing), so a folder you made by hand at a guard path is local data; files written inside a recorded guard folder later count as its output and are deleted with it) are regenerated by [`workler apply`](/reference/cli/apply) and [`workler setup`](/reference/cli/setup), so they are not local data, whether they are ignored or merely untracked. A copied `.env` you edited inside the workspace no longer matches its source, so it is local data (`apply` would refuse to overwrite it without `--force` too), and so is a file that was at a destination before its rule was added. A rule destination that is a tracked file still counts when it differs from the commit.
  - **An empty `.worktrees/`.** That is where Workler keeps its lock, so a nested workspace you already removed, or a group command that locked this repository as one of its sources, leaves the empty directory behind and it holds nothing. A non-empty one holds [nested workspaces](/guide/nested-workspaces) and counts.
- Refuses if any commit reachable from the workspace’s **refs, HEAD or reflogs** is not proven preserved in its surviving source repository. This covers noncurrent branches, detached HEAD, tags, custom refs, every stash entry still in the stash reflog (including index/untracked parents), and reflog-only commits after amend/reset/rebase. Inspection failure is **unknown**, never safe.
- `main` can never be removed.

A workspace you ran [Portler](https://github.com/YJJosh/Portler) in holds its state in an ignored `.portler/`, which counts as local data like any other ignored folder. Stop its services and clear that state first (`portler down`, then `portler clean`); `--force` would delete the folder while the services keep running.

Removal is plain directory deletion. A nonempty nested `.worktrees/` blocks normal removal; remove children from their own level first. Workler does not recursively assess or import nested repositories. **`--force` deletes them too**, without preserving anything.

## History preservation policy

The same read-only, offline assessment powers [`workler status`](/reference/cli/status). A commit counts as preserved only when it is **reachable** from a direct local branch (`refs/heads/*`), a direct tag (`refs/tags/*`), or a detached HEAD in the immediate source repository. A symbolic HEAD on a local branch is covered by that branch. Symbolic ref aliases, source reflogs/stashes, custom refs, **all remote-tracking refs**, and `refs/workler/*` / `refs/workler-group/*` synchronization mirrors do not count. In particular, `branch-sync` mirrors are pruned after workspace removal and are **not a backup**. Loose object presence does not count either: local clones can hardlink objects without keeping a surviving ref to them.

This deliberately conservative proof does not fetch or mutate refs. Even a pushed commit is blocked until it is imported into a durable source branch/tag (or detached source HEAD). The source must be a usable independent repository, not missing, broken, symlinked or a linked `git worktree` checkout. Shallow history, replace refs, grafts, alternate/shared object stores and partial clones are not supported by the proof and produce **unknown** in either repository. <!-- REVIEW: Reftable manifests can depend on external refs without symlinks. -->
Symlinked Git refs/objects/logs, external reftable table paths, missing objects, Git warnings/errors, and exceeding a per-command 30-second or 32-MiB output limit (or 30 seconds / one million filesystem entries while inspecting Git metadata) also produce unknown. Do not run concurrent Git ref edits, reflog expiration or garbage collection during assessment/removal; Workler locks coordinate Workler commands, not arbitrary Git processes.

The check covers commits still named by refs/HEAD/reflogs, not already expired/pruned history or unreachable dangling objects. It preserves commit reachability, **not branch/tag names, annotations or stash slot metadata**. Importing a stash commit retains its parents and committed trees, but does not recreate a stash slot or restore rewritten work. Workler never auto-stashes, commits, resets, rewrites history or makes a rescue archive.

## Preserve work, then remove

1. Run `workler status` from the source project (the group root for a group workspace).
2. Review the listed commits. The refusal/status gives up to five full IDs and a **Bash / Git Bash** import command for one specific commit into a suggested unused `refs/heads/keep-<id>` source branch. Choose another unused branch name if desired; do not force-fetch over an existing branch. The command escapes unusual paths and does not depend on a workspace branch name. It is not PowerShell/cmd syntax; on Windows use Git Bash, or pass the same literal arguments using your shell’s quoting rules.
3. Run that import only after deciding to retain the commit, then rerun status for any remaining commits. Keeping one tip also keeps its ancestors; unrelated old stashes or rewritten commits can require separate branches. For a group, import into **that member’s source**, not a different member or the group folder.
4. Separately preserve any uncommitted, staged, untracked or ignored files you need. **Importing history does not back up those files**, including data inside regenerable rule/setup outputs. Then run normal `workler remove`.

For ordinary names, this template run in the source imports an exact commit without changing its working tree (replace `FULL_COMMIT_ID` with an ID from status and choose an unused destination branch):

```bash
src=$(workler path 'feature-a') && git fetch --no-tags -- "$src" 'FULL_COMMIT_ID:refs/heads/keep-feature-a'
workler status
workler remove feature-a
```

Do not silently restore or discard intentionally rewritten commits. If the user chooses to discard them, `--force` is the explicit destructive override; it saves **no files or history**.

## Project groups

In a [project group](/guide/project-groups), the guard covers every member clone (each judged against its own source repository's `.workler`), and the workspace folder must hold nothing but the members, an unchanged `.workler` copy, and what the group's own rules and `--if-missing` lines produce (plus `.workler-setup.json`, Workler's record of the latter, while it is a regular file that reads exactly as Workler writes it): a nested `.worktrees/`, a member directory that is not a clone, a repository at a member's path that is not the recorded clone of that member (an unrelated repository dropped there, or a clone made for another workspace or location), or a symbolic link or file sitting at a member's path or at any folder on the way to it (whatever the link points at; it is never followed) all count as local data. A member that was never cloned holds nothing and does not block removal. The `.workler` copy is harmless only while it is a regular file that still matches the group's file; once you edit it (for example to configure nested group workspaces), replace it with a symbolic link (even one pointing at the group's file), or the group's `.workler` changes after the workspace was created, it counts as local data. File errors list every reason. After file checks pass, history is preflighted for all existing member clones against their proper source repositories before any directory is deleted. Any unsafe or unknown member blocks the whole removal; missing/broken/linked sources fail closed. A missing member holds no history to assess.

## Options

| Flag | Description |
| --- | --- |
| `--force` | Destructively delete despite local files, unpreserved history or unknown inspections; makes no backup |

## Output

```text
removed feature-a
```

## Errors

- No workspace named `<name>`.
- Workspace has local data (without `--force`): `workspace has local changes: <path>`, followed by what was found, one entry per line as Git spells it (`uncommitted: README.md`, `untracked: notes.txt`, `ignored: .portler/`), the first ten of them. A name holding a control character, a bidirectional-text control, a line or paragraph separator, a quote or a backslash is printed quoted with C-style escapes (`untracked: "a\nb"`), so it stays on its own line. In a project group each reason is listed, with a member clone's entries under it.
- Unpreserved or unknown Git history (without `--force`): refusal lists affected members, bounded commit IDs and exact-commit import advice. API code: `WORKSPACE_HISTORY`. Existing file errors take precedence.
- `<name>` is `main`.

## Examples

```bash
workler status
# Import listed commits into durable source branches and save local files first.
workler remove feature-a
workler remove broken-experiment --force   # intentional destruction, no backup
```
